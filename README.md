# MurojBlog

> 孟然君的个人博客 —— 写些想法和日常。
> 纯静态、零依赖，托管在 GitHub Pages 上。

没有框架、没有数据库、没有服务器；文章用 Markdown 写，一条命令生成网页。

## 写一篇文章

```bash
# 1. 生成草稿（自动带日期和 front matter 模板）
python build.py new "我的第一篇笔记"

#    想要简短的英文网址，就在后面再加一个文件名
python build.py new "我的第一篇笔记" my-first-note

# 2. 用任意编辑器（VS Code / Typora / 记事本）打开 posts/ 下新出现的 .md，写正文

# 3. 生成网页
python build.py

# 4. 本地预览
python -m http.server 8080        # 打开 http://localhost:8080

# 5. 发布
git add . && git commit -m "new post" && git push
```

其他命令：

```bash
python build.py list                    # 列出所有文章
python build.py url https://你的地址     # 一次性改好全站网址（部署前跑一次）
python build.py check                   # 检查转换、本地链接和生成结果，不修改文件
python build.py preview                 # 打开本地预览；修改 Markdown、页面、样式后自动刷新
```

构建脚本需要 **Python 3.10 或以上**，不需要安装第三方库。`python build.py build` 与 `python build.py` 等效。

`check` 会指出日期、文章网址、页面标记、缺失图片/视频、无效段落链接和未更新的生成文件；有问题时返回非零状态，方便 Agent 判断是否可以发布。它只检查本地文件，不检查外部网站是否在线。

`preview` 默认打开 <http://127.0.0.1:8080/>，按 `Ctrl+C` 停止。端口被占用时可用 `python build.py preview --port 8081`；加 `--no-browser` 可只启动服务。预览与正式构建使用同一套转换代码，但生成结果暂存在内存，不覆盖本地 HTML。修改有错误时保留上次成功的预览，并在终端提示原因。修改 `build.py` 本身后需要重启预览。

建议写作时开着预览，准备发布时依次运行 `python build.py`、`python build.py check`，再核对并提交推送。正式构建会先转换完全部页面，再更新文件；转换失败不写入半成品，写入失败会尝试恢复原文件。

> **工作原理**：`posts/*.md` 是文章内容的唯一来源。`build.py` 会
> ① 把每篇 `.md` 渲染成 `posts/<同名>.html`；
> ② 把首页卡片写进 `index.html` 的 `BUILD:POSTS` 标记之间；
> ③ 把归档列表、标签按钮、文章总数写进 `archive.html` 的对应标记之间；
> ④ 更新首页、归档、关于、小工具页共用的页头和页脚；
> ⑤ 重新生成 `sitemap.xml` 与 `feed.xml`。
> 首页、关于等页面在生成标记之外的正文仍可手工编辑；文章内容请改 `posts/*.md`。共用导航和页脚请改 `build.py` 中的 `header_block()` / `footer_block()`，再运行构建命令。请保留各对 `BUILD:…:START / END` 标记，标记缺失、重复或颠倒时构建会明确失败。

## 站内的各种交互

`js/enhance.js` 里每个效果都会先检查页面上有没有对应元素，没有就静默跳过。
全部尊重 `prefers-reduced-motion`，鼠标相关效果在触屏设备上自动关闭。

| 效果 | 触发方式 |
| --- | --- |
| **主题圆形扩散** | 点右上角主题按钮，新主题从按钮位置扩散铺满全屏（View Transitions） |
| **首页柔光跟随光标** | 鼠标在首页大标题区域移动，背景光晕带阻尼跟着走 |
| **卡片 3D 倾斜** | 鼠标划过首页文章卡片，卡片微微朝光标倾斜并有一道高光 |
| **命令面板** | `Ctrl` / `⌘ + K`，或按 `/`，或点页头放大镜；模糊搜索标题/标签/摘要/正文 |
| **文章目录** | 文章页自动生成；窗口 ≥1200px 时浮在左侧，滚动时高亮当前小节 |
| **打字机标题** | 首页大标题逐字敲出（每次随机 1~2 秒），敲完光标不消失、按固定频率闪；2 秒后光标一路左移，文字像按住退格键一样被删掉，再逐字敲出第二句标语，之后永久保留。只有一行时标题不留空，敲到第二行时把下面的副标题和按钮丝滑「顶开」一格 |
| **首屏依次淡入** | 首页的标签 / 标题 / 正文 / 按钮按 80ms 间隔逐个浮现，然后标题才开始打字 |
| **回到顶部** | 向下滚 420px 后右下角出现，圆环显示阅读进度 |
| **继续阅读** | 文章读到 8%~92% 后离开，再回来时底部提示「上次读到 N%」 |
| **卡片长大成文章** | 点首页卡片，卡片原地放大变形成文章标题（跨页面 View Transition） |
| **404 像素小游戏** | 打开任意的错误地址 |
| **生日彩蛋** | 每年 10 月 20 日打开首页，见下一节 |

> **继续阅读为什么是提示而不是自动跳转？** 自动把页面滚到中间会让人以为加载出错，
> 给一个可以点也可以忽略的小条更稳妥。提示 14 秒后自动消失。

> **卡片→文章的转场**需要浏览器支持 Cross-Document View Transitions
> （Chrome 126+ / Safari 18.2+）。不支持的浏览器就是普通跳转，没有副作用。

> **首页大标题的两句标语**都写在 `index.html` 的 `<h1>` 上：
> 标签之间的文字是动画结束后永久留下的那句，`data-tw-first` 属性里是刚打开页面时先敲出来的那句。
> 两条不一样才会播「删掉重敲」的换字动画；不想换字就删掉 `data-tw-first`。
> 关掉 JS 或开了系统「减少动态效果」时，直接显示最终那句，没有光标。
>
> 标语第一行期间标题只有一行高（下方不留空）。第一行打完时才会给 `<h1>` 加上 `.is-two-line`
> 把第二行的高度空出来，同时用 FLIP 在 320ms 内把副标题和按钮滑下去 —— 所以看到的是
> 「文字把下面的内容顶开」，而不是整块内容跳一格。

## 生日彩蛋（10 月 20 日）

代码在 `js/birthday.js`，**只在 `index.html` 加载**，其他页面没有。

每年 **10 月 20 日**打开首页时：

1. **左下角和右下角**各喷出一轮礼花（canvas 粒子，带重力、阻力、旋转、渐隐）
2. hero 右侧的空白区浮现一个**简约蛋糕**（两层 + 滴落奶油 + 一根会摇曳的蜡烛）
3. **点蛋糕** → 蛋糕「缩小 → 弹回原样」+ 一声**小黄鸭「嘎」** + 再放一轮礼花

### 几个约束

- **礼花最多放 10 轮**（进页面算第 1 轮，之后每点一次 +1）。放满 10 轮后底部会弹一句
  「礼花放满 10 次啦，浏览器也要喘口气 🎂」，再点只有蛋糕动画和音效，不再喷粒子。
- 同时存在的粒子有 **700 个上限**，超了就不再生成，防止被连点拖垮。
- 鸭子叫是 **Web Audio 现场合成**的（两段带音高扫频的锯齿波过带通滤波），
  **不需要任何音频文件**，也不会发起网络请求。
- 遵循 `prefers-reduced-motion`：关掉动效偏好时不喷粒子、不播缩放动画，只留蛋糕。

### 想提前看效果

不用等到 10 月 20 日，在地址后面加 `#birthday` 就能强制启用：

```
http://localhost:8080/index.html#birthday
```

### 想改日期 / 次数

`js/birthday.js` 开头几行：

```js
var BIRTHDAY_MONTH = 9;      // 0 = 一月，所以 9 = 十月
var BIRTHDAY_DAY = 20;
var MAX_BURSTS = 10;         // 礼花最多放几轮
var PER_BURST = 72;          // 每一角每轮喷多少颗粒
var MAX_PARTICLES = 700;     // 全屏同时在跑的颗粒上限
```

## 文章格式

每篇 `.md` 开头是一段 front matter：

```markdown
---
title: 文章标题
date: 2026-10-02
tags: 随笔, AI
summary: 一句话摘要，显示在首页卡片与归档列表里。
ai: true
---

正文从这里开始。
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章标题 |
| `date` | 建议 | `YYYY-MM-DD`，决定排序；不写则用文件修改时间 |
| `tags` | 否 | 逗号分隔；第一个标签显示在首页卡片左上角，全部标签自动进入归档筛选栏 |
| `summary` | 否 | 摘要，用于卡片、归档列表、搜索描述与 RSS |
| `ai` | 否 | `true`/`false`，标题下是否显示「由AI生成」标签，默认 `true` |
| `minutes` | 否 | 手动指定「约 N 分钟读完」；不写则按字数自动估算 |
| `type` | 否 | 写 `video` 表示这篇是视频页：卡片上显示「视频 / 观看 →」而不是「约 N 分钟读完」，见下面「只有一段视频的文章」 |
| `slug` | 否 | 自定义输出文件名 |

字段值可以使用成对的单引号或双引号，例如 `date: "2026-11-12"`、`slug: "my-post"`。日期不合法、阅读分钟数不是正整数、文章网址重复（不区分大小写）时会直接指出文章文件名。`slug` 请使用中文、字母、数字、连字符或下划线，不要填写目录或完整网址。

### 支持的 Markdown 语法

| 写法 | 效果 |
| --- | --- |
| `## 标题` / `### 标题` | 二级 / 三级标题（`#` 也当二级标题） |
| `**粗体**` `*斜体*` `` `行内代码` `` `~~删除线~~` | 行内样式 |
| `[文字](链接)` `![说明](图片)` | 链接与图片（图片自动加 `loading="lazy"`） |
| `- 项目` / `1. 项目` | 无序 / 有序列表，**缩进两格即可嵌套** |
| `> 引用` | 引用块 |
| ` ```语言 … ``` ` | 代码块，自动带「复制」按钮 |
| `\| 表格 \|` | 表格（表头下一行写 `\| --- \| --- \|`） |
| `---` | 分隔线 |
| `<br>`、`<span>` 等原生 HTML | 原样保留，可用来做特殊排版 |
| `<video>` / `<iframe>` 单独成段 | 整段原样输出、不套 `<p>`，适合嵌视频 |

段落里**换行不会变成空格**：中文之间自动直接相连，英文之间才补空格，
所以一行写多长、随时回车断句都不影响最终排版。

### 只有一段视频的文章

`posts/video.md` 是现成的例子：正文只有一行 `<video>`，一个字的正文都没有。

1. 把视频文件放进根目录的 `video/` 文件夹，例如 `video/demo.mp4`；
2. 打开 `posts/video.md`，把 `<video ... src="../video/xxx.mp4">` 里的文件名改成你的；
3. 运行 `python build.py`，再刷新 `posts/LonlyHalloween.html`。

视频放在 B 站的话，把那行 `<video>` 换成
`<iframe src="https://player.bilibili.com/player.html?bvid=这里填BV号" allowfullscreen></iframe>`，
宽度会自动铺满正文、按 16:9 显示。

正文里没有文字时，首页卡片和归档列表会自动省掉摘要那一行（不会留一块空白）；
想给卡片加一句话，就在 front matter 里补 `summary:`。

## 关于页的姓名彩蛋（支持多个名字）

关于页那个「孟然君」是可以玩的，而且**名字数量不限**。

**桌面端**

1. 鼠标移到「孟然君」上 → 上方拉出菜单，复选框亮起并一笔画出对勾
2. **滚动滚轮上/下** → 复选框在名字列表里上下滑动，显示的名字跟着滚入滚出
3. 鼠标移开后**菜单保持展开**（按 `Esc` 或点别处才收起）
4. 下方描述跟着一起替换

电脑也可以直接点击名字：三个名字时依次为 **孟然君 → Muroj → Mengranjun → Muroj → 孟然君**，重复往返。在两端会自动折返；滚轮仍按上下方向选择。

滚到列表两端时会**放行滚动事件**，页面正常滚动，不会把人「卡」在名字上。

**移动端**：轻点使用同样的往返顺序，菜单会自己收起。

**键盘**：`Tab` 聚焦后按 `↑` / `↓` 切换；`Enter` 或空格与点击相同，按往返顺序切换。

**数字键直接跳**：菜单展开时，按 `1` `2` `3` … 直接跳到第 n 个名字。
序号是 JS 自动加到每个选项前面的，**加名字时不用手写序号**。
（在输入框里打字、或命令面板打开时不会抢数字键。）

### 再加一个名字

只需在 `about.html` 的 `.about-swap-multi` 中追加一段：

```html
<p data-name="新名字">写下这个名字的由来或介绍。</p>
```

`data-name` 是显示的名字，标签内是对应介绍；段落顺序就是切换顺序。菜单、序号和名字舞台自动生成，**不必改 JavaScript，也不必再维护多份名单**。四个名字时自动变为 `1→2→3→4→3→2→1`；只有一个名字时保持不变。

中文名自动用衬线体、纯英文名自动用无衬线粗体，不用手动设置字体。名字区域宽度和介绍高度都跟随当前选中项调整。第一段保留 `class="is-on"` 作为禁用 JavaScript 时的默认介绍，其余段落不用加该 class。

样式在 `css/style.css` 里搜索「姓名彩蛋」，逻辑在 `js/enhance.js` 里搜索 `aliasSwitcher`。
`about.html` 中也保留了添加示例；原有备份页的两段介绍写法仍然兼容。

## 部署到 GitHub Pages

1. 在 GitHub 新建**公开**仓库，命名为 `你的用户名.github.io`
   （想要 `https://用户名.github.io` 这样的短域名就必须这么命名）
2. 推送代码：

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/你的用户名/你的用户名.github.io.git
git push -u origin main
```

3. 仓库 **Settings → Pages → Build and deployment**，选 **Deploy from a branch**，
   分支 `main`、目录 `/(root)`，保存。约一分钟后访问 `https://你的用户名.github.io`

4. **把网址改对**（重要，只跑一次）：

```bash
python build.py url https://你的用户名.github.io
```

这条命令会自动帮你改好 `build.py` 里的配置、四个静态页里写死的
`canonical` / `og:url` / `og:image` 地址、以及 `sitemap.xml`、`feed.xml`，
然后重新构建一遍。改完记得 `git add . && git commit -m "set site url" && git push`。

> 用普通项目仓库（如 `my-blog`）也可以，此时网址是
> `https://你的用户名.github.io/my-blog`，那么第 4 步就写这个完整地址。

## 本地预览

直接双击 `index.html` 也能看，但推荐起一个本地服务器（路径和线上一致）：

```bash
python -m http.server 8080
# 访问 http://localhost:8080
```

---

## 环境要求

只需要 **Python 3.8+**，不需要 `pip install` 任何东西 —— `build.py` 只用标准库。
Windows 下控制台编码会在脚本里自动切成 UTF-8，不会出现中文乱码。
