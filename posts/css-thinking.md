这个模板没有使用 React、Vue、Tailwind 或任何构建工具。整个站点的"依赖清单"是零。这不是复古情怀，而是一组经过权衡的工程决策。

## 决策一：CSS 变量做主题系统

深浅色主题切换听起来像是需要状态管理库的场景，实际上原生 CSS 自定义属性就足够。所有颜色定义在 `:root` 与 `[data-theme="dark"]` 两组变量里，切换主题只是切换 `html` 标签上的一个属性：

```css
:root { --bg: #f4f9fb; --text: #1b2a31; }
[data-theme="dark"] { --bg: #0c1418; --text: #c2d2d9; }

body {
  background: var(--bg);
  color: var(--text);
  transition: background-color 0.3s ease;
}
```

## 决策二：系统字体栈优先

Web 字体是博客首屏最常见的性能杀手。模板使用系统字体栈——中文走苹方/微软雅黑，标题走 Georgia/宋体类衬线——零下载、零布局偏移，且在各平台上都有得体的观感。

## 决策三：动画只碰 GPU 属性

所有过渡动画只使用 `transform` 和 `opacity`，这两个属性由合成器处理，不触发重排重绘。配合 `prefers-reduced-motion` 媒体查询，照顾对动效敏感的用户。

## 决策四：交互保持最小化

全站 JavaScript 不到 100 行，只做四件事：主题切换、移动端菜单、阅读进度条、滚动渐入。没有框架意味着没有 hydration 成本、没有包体积焦虑，十年后这份代码依然能跑。

## 小结

工具的价值取决于场景。对一个以阅读为核心的静态博客，原生 Web 平台提供的能力已经足够好，而"足够好"恰恰是最难做到的标准。
